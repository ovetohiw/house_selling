# PLANS.md

Политика: когда exec plan обязателен, где живёт, как закрывается.
Карта разделов, plan-once и старт сессии исполнения — канон в [exec-plans/index.md](exec-plans/index.md). Не дублируйте сюда шаблоны этапов.

## Когда план обязателен

Создавайте exec plan, когда работа:

- занимает более одной сессии
- меняет более одной подсистемы
- имеет нетривиальные риски верификации или раскатки
- зависит от открытых решений, которые должны быть зафиксированы

## Где живут планы

| Путь | Назначение |
|------|------------|
| `.cursor/exec-plans/inprogress/task/` | плановая работа не-бага и не big-task |
| `.cursor/exec-plans/inprogress/bug/` | дефект: repro → fix → verify |
| `.cursor/exec-plans/inprogress/big-task/` | много сессий / подсистем / решений |
| `.cursor/exec-plans/inprogress/big-task/hot-fixes/` | отклонение этапа родительского decompose |
| `.cursor/exec-plans/completed/` | один `YYYY-MM-DD-short-topic/` + один `*-result.md` |
| `.cursor/exec-plans/ranking/` | оценка A–D каждой закрытой работы |

У `task` / `bug` / `big-task` состав одинаковый: папка + `*-plan.md` + `*-decompose.md`. Hot-fixes — только у big-task. Шаблоны — в `index.md` соответствующего раздела.

## Plan-once (кратко)

1. **Планирование** — заполняются plan (включая карту контекста) и decompose с годными этапами.
2. **Исполнение** — старт по AGENTS (PROGRESS → HANDOFF → FEATURE → роль); этапы decompose только роль `developer` при фазе `build`; soft/hard — в [AGENTS.md](../AGENTS.md); роли — [roles/index.md](roles/index.md); чеклист этапа — `.cursor/exec-plans/index.md`.
3. Тексты этапов после старта исполнения не переписывают. Отклонение **смысла** этапа — hard (big-task: hot-fix, если не меняет смысл остальных этапов; иначе открытые решения + стоп). Soft-решения в скоупе цикл не блокируют.

Не начинайте исполнение, пока карта контекста заполнена и как минимум текущий + следующий этапы годны. Полные минимальные секции plan/decompose — в type-index.

## Правила работы

- У одного активного плана один текущий шаг (поле в plan).
- Статусы этапа обязательны на каждом переходе цикла ([AGENTS.md](../AGENTS.md)): plan «Текущий шаг» и чекбокс текущего этапа в decompose всегда совпадают (`в очереди` → `в работе` → `верификация` → `готово`). После старта исполнения текущего этапа оставлять его в `в очереди` запрещено; лог plan обновлять по мере работы — plan не статическая проза.
- Soft-решение в скоупе этапа — записать в открытые решения / лог и продолжить. Смена смысла этапа или направления plan — hard: зафиксировать в plan (карта контекста / открытые решения) или оформить hot-fix для big-task (без смены смысла остальных этапов); этапы `*-decompose.md` не переписывать; к человеку — по soft/hard в AGENTS.md.
- После закрытия текущего этапа — handoff и стоп; соседний этап в том же прогоне не стартовать.
- При завершении:
  1. `.cursor/exec-plans/completed/YYYY-MM-DD-short-topic/` с одним `*-result.md` (гейты AGENTS пройдены, структурированная «Верификация», Hot-fixes и «Оценка качества» по фактам верификации);
  2. строка в реестре completed и в [exec-plans/ranking/](exec-plans/ranking/index.md);
  3. удалить целиком папку активной работы `.cursor/exec-plans/inprogress/{task|bug|big-task}/YYYY-MM-DD-short-topic/` (не оставлять пустую); для `big-task` — также удалить связанные папки в `inprogress/big-task/hot-fixes/YYYY-MM-DD-.../` после переноса сути в result; каркас типов (`task/` / `bug/` / `big-task/` / `hot-fixes/` и их `index.md`) не трогать; в FEATURE поле `Exec plan:` сбросить в `нет`, если фича закрыта вместе с планом. Запрещено очищать содержимое и оставлять пустую папку.
- Не удаляйте историю без сводного `*-result.md` и записи в ranking.
